ABOUT THIS DEMO

ILLUSTRATIVE DATA — NOT A REAL TEARDOWN

Silicon Teardown is an interactive concept tool. You pick a class of US guided weapon, "explode" it into a notional chip bill-of-materials, inspect each component's function / process node / (illustrative) supplier-fab-country, and watch a computed Fragility Score react when you sever a semiconductor chokepoint.

What is real

  • The subsystem taxonomy is grounded in general public knowledge of guided-munition electronics: seekers / image processors, FPGAs, IMU & MEMS gyros, RF front-ends, GPS/GNSS receivers, power-management ICs, memory, microcontrollers.
  • The fragility math is a real, transparent, deterministic formula (concentration + foreign/single-source + low substitutability + chokepoint exposure) — you can see every input in the decomposition bars, and the retaliation toggle genuinely re-computes it live.
  • The named chokepoints (advanced-node foundry, EUV lithography, leadframe/OSAT packaging, specialty RF/compound-semi) reflect real, widely-discussed structural pressure points.

What is illustrative / placeholder

  • Every specific component, supplier, fab, country-of-origin, node, and part reference is INVENTED to demonstrate the tool. Real board-level chip BOMs for fielded US weapons are largely non-public.
  • Supplier names shown are archetypes ("advanced-node foundry," "domestic FPGA vendor"), not attributions of any real part to any real program.
  • The fragility weights are reasonable but not calibrated against classified or proprietary reality.
  • There are deliberately no citations — fake-precise sourcing would be worse than none.

What it would take to go live

  • Primary teardown research: physical decap / X-ray / die-marking analysis, or vetted trade-press and procurement-record sourcing, to establish a real BOM per system.
  • FOIA & supply-chain disclosures and DMSMS (diminishing-sources) records for supplier/fab mapping.
  • Expert verification (Jordan + subject-matter reviewers) on every node, supplier, and chokepoint claim.
  • Calibrated weights for the fragility model, ideally validated against historical disruption events.
  • This page itself stays static — no API keys or server needed. A production version would add a sourced, reviewable dataset behind the same UI.

How to run

Open index.html directly, or serve with python3 -m http.server. No build step, no dependencies beyond Google Fonts.
